# Messages & Localization

RainTools uses a flexible language file system that supports full message customization and multiple languages. Messages are stored in YAML files in the `plugins/RainTools/lang/` directory.

## Language File Location

Language files are located at:
```
plugins/RainTools/lang/
├── en.yml  (English)
└── es.yml  (Spanish)
```

## Setting the Language

Configure the active language in [config.yml](/configuration/config-file):

```yaml
general:
  language: "en"  # or "es" for Spanish
```

After changing the language, reload the configuration:

```bash
/rainarea reload
```

## Language File Structure

Language files are organized into sections for different message types:

```yaml
# Special prefix messages
prefix: "&6[Rain Tools]"
error-prefix: "&c[Rain Tools]"
success-prefix: "&a[Rain Tools]"
info-prefix: "&e[Rain Tools]"

# Error messages
errors:
  no-permission: "%error-prefix% You don't have permission..."
  area-not-found: "%error-prefix% Area '%area%' not found."
  # ... more errors

# Success messages
success:
  area-created: "%success-prefix% Area '%area%' created successfully."
  # ... more success messages

# Informational messages
info:
  no-areas: "%info-prefix% No areas configured."
  # ... more info messages

# Area status indicators
area-status:
  active: "&a[ACTIVE]"
  inactive: "&e[INACTIVE]"
  disabled: "&c[DISABLED]"

# Area information display
area-info:
  world: "&f- World: &e%world%"
  # ... more area info

# Command help
help:
  rainarea:
    header: "%prefix% Available commands:"
    # ... command descriptions
  saveitem:
    # ... item command descriptions
```

## Available Placeholders

Placeholders are replaced with dynamic values at runtime. Use the pattern `%placeholder%`.

### Prefix Placeholders

<ParamField path="%prefix%" type="string">
  Main plugin prefix (defined at top of language file)
</ParamField>

<ParamField path="%error-prefix%" type="string">
  Error message prefix (typically red)
</ParamField>

<ParamField path="%success-prefix%" type="string">
  Success message prefix (typically green)
</ParamField>

<ParamField path="%info-prefix%" type="string">
  Information message prefix (typically yellow)
</ParamField>

### Dynamic Placeholders

<ParamField path="%area%" type="string">
  Area name in area-related messages
</ParamField>

<ParamField path="%item%" type="string">
  Item name in item-related messages
</ParamField>

<ParamField path="%value%" type="string">
  Generic value (used for configuration values, counts, etc.)
</ParamField>

<ParamField path="%world%" type="string">
  World name when displaying area information
</ParamField>

<ParamField path="%x%" type="number">
  X coordinate
</ParamField>

<ParamField path="%y%" type="number">
  Y coordinate
</ParamField>

<ParamField path="%z%" type="number">
  Z coordinate
</ParamField>

<ParamField path="%volume%" type="number">
  Area volume in blocks
</ParamField>

<ParamField path="%count%" type="number">
  Count of items or areas
</ParamField>

<ParamField path="%chance%" type="number">
  Probability percentage (for item drop chances)
</ParamField>

<ParamField path="%entity%" type="string">
  Entity type name
</ParamField>

<ParamField path="%error%" type="string">
  Error message text
</ParamField>

## Creating a Custom Language

To create a new language (e.g., French):

1. **Copy an existing language file:**
   ```bash
   cp plugins/RainTools/lang/en.yml plugins/RainTools/lang/fr.yml
   ```

2. **Translate all messages:**
   Edit `fr.yml` and translate each message while keeping:
   - Placeholders intact (e.g., `%area%`, `%item%`)
   - Color codes as desired
   - The same YAML structure

3. **Set the language in config.yml:**
   ```yaml
   general:
     language: "fr"
   ```

4. **Reload the plugin:**
   ```bash
   /rainarea reload
   ```

## How the Message System Works

The message system uses the `LanguageManager` class (see `LanguageManager.java:70`). When a message is requested:

1. **Load message** from language file using message path (e.g., `errors.area-not-found`)
2. **Replace prefix placeholders** (`%prefix%`, `%error-prefix%`, etc.)
3. **Replace custom placeholders** with provided values
4. **Convert color codes** from `&` to Minecraft's internal format
5. **Send to player** or console

### Message Usage in Code

```java
// Simple message
String msg = languageManager.getMessage("errors.no-permission");

// Message with placeholders
Map<String, String> placeholders = new HashMap<>();
placeholders.put("area", areaName);
String msg = languageManager.getMessage("success.area-created", placeholders);
```

## Fallback Behavior

If a message is not found in the current language file:

1. The plugin displays: `Missing message: <path>`
2. Check the console for warnings
3. Ensure your language file has all required keys

If a language file doesn't exist:

1. Plugin falls back to English (`en.yml`)
2. If English doesn't exist, it's extracted from plugin resources

## Best Practices

<Warning>
  Always keep placeholders in their original form when translating. Don't translate `%area%` to `%zone%` or messages will break.
</Warning>

<Tip>
  Test your custom messages by using commands that trigger them. Use `/rainarea help` to see all available commands.
</Tip>

<Note>
  Color codes and formatting are subjective. Choose colors that match your server's theme and provide good contrast for readability.
</Note>

## Reloading Messages

After editing language files:

```bash
/rainarea reload
```

This reloads all language files without restarting the server. Changes take effect immediately for all players.
